# Decision Log

## 2026-06-09
- Initialized PRD workspace.
- Based PRD creation on the previously finalized Product Brief.
- User selected "Coaching path" using the "Vision + Features" entry point.
- Identified the 4 Core Capabilities for V1:
  1. Data Ingestion (YGOJSON v0.6.0).
  2. Functional Categorization (Auto-Tagging).
  3. Math Engine (Multivariate Hypergeometric Distribution with anti-overflow).
  4. Counter-Matching Intelligence (Meta Choke-Point Analysis).
- Decision (F1): Ingestion uses a local cache model (e.g. `--update` flag) rather than downloading the multi-megabyte YGOJSON zip on every run.
- Decision (F1): Missing fields in cards (like `series` or `text`) are handled gracefully without crashing. Normal monsters are retained (as potential "Garnets"), missing series default to "Generic".
- Decision (F1): Strict pre-filtering is enforced using the `formats` field to exclude forbidden cards and irrelevant formats (Rush, Speed Skills) to optimize RAM usage.
- Decision (F2): Categorization uses strict Regular Expressions (Regex) leveraging Konami's standardized PSCT, avoiding heavy ML/NLP.
- Decision (F2): System supports Dynamic Multi-Tagging (e.g. a card can be both a Starter and an Extender). The simulator determines the optimal role at calculation time.
- Decision (F2): Rules for categorization are stored in an external, user-editable configuration file (JSON/YAML) to ensure long-term maintainability without code changes.
- Decision (F3): Absolute precision is prioritized over execution speed. A Monte-Carlo simulation with up to 100k iterations is allowed to take 15-30 seconds to evaluate complex multi-tag hands.
- Decision (F3): User targets are defined via a dedicated configuration file (`target_combos.yaml`) rather than complex CLI arguments, serving as a clean API precursor for the V2 Web interface.
- Decision (F3): The engine must compute 5-card (Turn 1) and 6-card (Turn 2) hands simultaneously, and fully simulate the draw/dig effects of "Resource Generators" to dynamically update probabilities.
- Decision (F4): Meta targets and choke points are defined by the user in an external file (`meta_targets.yaml`), avoiding hardcoded meta dependencies.
- Decision (F4): Immunity is determined by simulation rather than hardcoded tags. The engine simulates archetype combos under the effect of the chosen counter (e.g. Dimension Shifter) and selects archetypes with a 100% success rate under those conditions.
- Decision (F4): Native support for the `.ydk` format is required for both importing user decks (Audit) and exporting the AI-generated optimal decks.
- Decision (F4): Deck size constraints are flexible (40-60 cards). The engine is allowed to exceed 40 cards if doing so mathematically dilutes the probability of drawing Garnets while maintaining the 85% Starter opening rate.
- PRD finalized and locked on 2026-06-09.
